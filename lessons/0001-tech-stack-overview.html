Lesson 0001 — Tech Stack Series

Understanding the Dual-Layer Architecture

Mission Context

You are learning the tech stack behind WhatsApp KDE Widget so you can build, debug, and extend KDE desktop apps with local headless web automation.

1. The Big Picture: Why Two Layers?

A native KDE Plasma 6 widget runs inside KDE's desktop process (plasmashell). However, WhatsApp does not provide an open public API for personal accounts. To solve this without reverse-engineering encrypted WebSockets, this project uses a dual-layer architecture:

  • Frontend (QML / Qt 6): Runs natively inside KDE Plasma. Provides fluid desktop UI, dark theme, right-click context menus, and native plasmoid integration.
  • Backend (Node.js + Puppeteer): A lightweight local daemon running Chrome in headless mode. It controls WhatsApp Web via DOM manipulation and exposes a clean local REST API on 127.0.0.1:8002.

2. The Data Flow Bridge

How do the desktop UI and the Node backend communicate?

+----------------------------------+          HTTP / REST          +----------------------------------+
|   KDE Plasmoid (QML / Qt 6)     |  --------------------->  |   Node.js Server (Express)      |
|  widget/contents/ui/main.qml     |  <---------------------  |   backend/server.js              |
+----------------------------------+   JSON (localhost:8002)   +----------------------------------+
                                                                             |
                                                                   Puppeteer Automation
                                                                             v
                                                                   +-------------------+
                                                                   |  WhatsApp Web     |
                                                                   |  (Headless Chrome)|
                                                                   +-------------------+

The QML frontend uses standard JavaScript XMLHttpRequest objects to send requests to local endpoints like /api/getAllChats, /api/getChatMessages, and /api/sendReaction.
